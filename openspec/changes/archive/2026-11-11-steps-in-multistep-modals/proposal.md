## Why

Newer wizards (`CreateTestSuite`, `ContainerCreate`, `ImportModal`, `AddMetricModal`) show progress with the
ui-kit `Steps` component and a shared `StepperModalButtons` footer. Five multi-step modals still swap a whole
`Popup` per step with no step indicator: the user cannot see how many steps remain, and each step resizes and
remounts the dialog. Nothing in the repo rules says a wizard must use `Steps`, so the split will keep growing.

## What Changes

- Move these modals onto one `Popup` + `Steps` + `StepperModalButtons`, like `CreateTestSuite`:
  - `CreateKeyModal` — Details → Roles → Key (reveal)
  - `DuplicatePlatformKeyModal` — Name → Key (reveal)
  - `KeyRotateModal` — Confirm → Key (reveal)
  - `CreatePolicyModal` (policies and policy assignments share it) — Details → Subjects
  - `CreateApplication` (Assets Applications) — Details → Source
- Add one optional prop, `isLastStepInformative`, to `StepperModalButtons`. When set, the second-to-last step
  shows **Finish** (the action, e.g. "Create") in place of Next, and the last step shows only **Close**.
- On an informative last step the modal marks every earlier step `disabled` through the existing `Step.disabled`
  field, so completed steps cannot be re-entered after the key was created. No ui-kit change.
- Add a rule to `.claude/rules/components.md`: every wizard or multi-step flow uses `Steps`.

No behavior of the create calls, validation, notifications, or post-create navigation changes.

## Non-Goals

- No change to `@epam/ai-dial-ui-kit` or the `Steps` component.
- No new component; `StepperModalButtons` is extended, not replaced.
- Wizards that already use `Steps` are untouched (apart from inheriting the unchanged default footer behavior).
- No change to key generation, the create/rotate server actions, or what the reveal step displays.

## Capabilities

### New Capabilities
- `multi-step-modals`: Contract for any multi-step modal: ui-kit `Steps` indicator, shared stepper footer, and the
  informative-last-step pattern.

### Modified Capabilities
- `platform-keys`: Create, Duplicate, and Rotate modals present their steps with `Steps`, with the key reveal as a
  locked informative last step.
- `platform-policies`: The create modal presents Details and Subjects as steps.
- `platform-policy-assignments`: Same shared create modal presents Details and Subjects as steps.
- `assets-application-creation`: The two-step creation modal presents its steps with `Steps`; the source step keeps
  its 540px bound.

## Impact

- Code: `Common/StepperModalButtons/StepperModalButtons.tsx`; the five modals above under
  `components/Assets/Platform/{Keys,PolicySubjects}` and `components/Assets/Entities/Apps`; their specs.
- Docs/rules: `.claude/rules/components.md` (§5, §12); generated Cursor/Copilot mirrors are regenerated by pre-commit.
- Shared component risk: `StepperModalButtons` is used by `CreateTestSuite`, `ContainerCreate`, `ImportModal`,
  `ImportConfig`, `AddMetricModal`, `EditRequestWizard`, `ImportFile`, `PickPublicDataset`. The new prop defaults to
  off, so their behavior must remain identical.
- The per-step `portalId`s of the reveal screens (`CreateKeyReveal`, etc.) go away with the per-step popups.
