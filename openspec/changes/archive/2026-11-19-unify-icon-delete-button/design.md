## Context

Two treatments of an icon-only delete exist side by side:

- `Common/RemoveButton`: `IconButton`, `Danger` + `Outlined`, ~20 consumers (red border).
- Hand-rolled `GhostIconButton` + `<IconTrashX className="text-error" aria-hidden />`, ~14 sites (borderless),
  using three different icon sizes (`BASE_BUTTON_ICON_PROPS`, `DIAL_ICON_SIZE.SM`, hardcoded `16`/`18`).

Labelled delete buttons are mostly `DangerButton` + `Outlined` + `iconBefore` (entity header wrappers,
`PromptDetails`, `AddNewTool`, `Datasets/TestCases/Header`), with three outliers: `MetricCard` and the
saved-query Delete in `QueryBuilder` (`GhostButton className="text-error"`), and Delete all in
`FileUploadField` (`NeutralButton`).

## Goals / Non-Goals

**Goals:**
- One component owns the look of a delete/remove control, labelled or not.
- Icon-only is borderless, labelled is bordered, everywhere.
- Writing the next delete button by hand is discouraged by a rule.

**Non-Goals:**
- Close/clear `IconX` buttons, grid action-menu items, ui-kit changes.

## Decisions

**1. Extend `RemoveButton` rather than add a new component.** Its name and ~20 call sites already exist;
keeping the name makes the migration a restyle for them and a swap for the hand-rolled sites. A new
`DeleteButton` would leave two components with overlapping jobs.

**2. One component, branch on `label`.** `label` present → `DangerButton` with `ButtonAppearance.Outlined`
and the trash as `iconBefore`; absent → `GhostIconButton` with the trash icon in `text-error`. The rule is
the one the user stated, so encoding it in the component makes a bordered icon-only button impossible
to produce. Props are a discriminated union kept in `Common/RemoveButton/models.ts` (code-standards: types
outside the component file). Alternative considered: two exports (`RemoveIconButton`, `RemoveLabelButton`).
Rejected: callers would pick the style again, which is the drift being removed.

**3. Spread order.** Defaults (`aria-label` = Delete, the icon) go before `{...props}`; the derived icon and
variant go after, per `components.md` §3, so a caller cannot reintroduce a border.

**4. Icon size is fixed inside the component** (`BASE_BUTTON_ICON_PROPS` for the labelled case,
`DIAL_ICON_SIZE.SM` for icon-only, as today). Callers no longer pass sizes; the hardcoded `16`/`18` sites
converge. `size` stays a passthrough for sites that use `ElementSize.Small` (`ResourceMultiAuth`).

**5. Wrappers that pass classes keep working.** `className` is forwarded (`mb-1 shrink-0`, `shrink-0`,
`LABELLED_FIELD_TOP_OFFSET`).

**6. "Clear" is not "delete".** `AppRunnersResource` uses `RemoveButton` with `aria-label=Clear`. It moves to
`GhostIconButton` + `IconX`, the pattern `SingleValueAutocomplete` already uses.

**7. Migration is mechanical and split by area** so each PR stays reviewable: shared component, then
Analytics, then the rest, then labelled buttons. Accessible names are unchanged, so existing role/name
queries in specs keep passing; `RemoveButton.spec.tsx` is rewritten for the two variants.

**8. Rule text.** Add to `components.md` §5 (reuse the design system first): "Before writing a control
that has a shared equivalent, use it; if a variant is missing, add it to the shared component. Delete/remove
is the standing example: use `Common/RemoveButton`, never a hand-rolled trash `IconButton`." Mirrors are
regenerated by pre-commit.

**9. Toast wrapping (#5602).** In `Notification.tsx` the description container gets `min-w-0 break-words`
(Tailwind `overflow-wrap: break-word`). `whitespace-pre-wrap` stays so multi-line messages keep their
newlines. If a browser check shows the kit's own message wrapper still clips, fall back to
`[overflow-wrap:anywhere]`, which also shrinks min-content.

## Risks / Trade-offs

- [Bordered buttons losing the border looks like a regression to someone] → called out in the proposal and
  covered by the delete-button spec.
- [Hit target shrinks where a bordered 32px button becomes a ghost one] → both are `IconButton` sizes from
  the kit; check Variable/KeyValueGrid rows for alignment during review.
- [Large file count] → mechanical changes, grouped into four PRs.
- [Grid cells] → grid delete actions use menu items and `actions.tsx`; untouched.
