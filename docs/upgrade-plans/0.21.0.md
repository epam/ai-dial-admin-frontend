# Upgrade Plan — 0.21.0

> Auto-generated from `docs/INFRA-CHANGELOG.md` — review before applying.

This release introduces the full DIAL Core API migration as a **Preview** and adds three optional Analytics preview variables. The migration itself adds no new environment variables: the action it requires is a recommended change to an existing one (`DISABLE_MENU_ITEMS`), because the preview surface is not behind a feature flag. Everything else has safe defaults.

---

## 1. High-Priority Changes

### 1.1 Configuration & API

| Setting              | Default | Required (Yes/No) | Description                                                                                                                                                                                      |
| :------------------- | :------ | :---------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DISABLE_MENU_ITEMS` | unset   | No                | Space-separated list of menu groups/items to hide. **Recommended: include `catalog`** while the Core API migration is Preview, so the Core-direct `Catalog` group is not exposed to admin users. |

Why this is High priority: unlike `Deployments`, `Evaluation`, and `Analytics`, the `Catalog` group has **no** feature flag in `MENU_CONFIGURATION` — it is always present in the menu config and is only removed by `DISABLE_MENU_ITEMS`. Without this change the preview surface becomes visible to every admin user immediately after upgrade.

Matching is case-insensitive against the last segment of each menu key (`Menu.Catalog` → `catalog`), and a group is dropped when its own key matches or when all of its items are filtered out.

**Helm `values.yaml`:**

The frontend is the `dial-extension` subchart aliased as `frontend` in the [dial-admin chart](https://github.com/epam/ai-dial-helm/tree/main/charts/dial-admin), so its variables belong under `frontend.env` (a key-value map), not a bare top-level `env:`.

```yaml
frontend:
  env:
    # Space-separated; add other groups/items to hide alongside `catalog`
    DISABLE_MENU_ITEMS: 'catalog'
```

## 2. Low-Priority / Optional Changes

### 2.1 Configuration & API

| Setting                           | Default | Required (Yes/No) | Description                                                                                                                                                                                                                                                                                                                                                  |
| :-------------------------------- | :------ | :---------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DIAL_CORE_API_URL`               | unset   | Yes               | Already required as of 0.19.0 — no new action. The Core-direct `Catalog` views additionally depend on it; the migration cannot be exercised while it is unset. The variable itself is not Preview — the migration is.                                                                                                                                        |
| `DIAL_ADMIN_API_URL`              | unset   | No                | No action for this release. Keep it set: it drives the `adminApiEnabled` flag, and when unset the admin-backend-backed `Entities`, `Builders`, `Access Management`, and `Audit` groups plus the Import/Export config actions are hidden. Clearing it is the end state of the migration, not a step to take while it is Preview.                              |
| `ANALYTICS_SESSIONS_ENABLED`      | `false` | No                | Preview. Enables the Sessions sub-item in the Analytics section. The flag resolves as `isValueTruthy(ANALYTICS_ENABLED) && isValueTruthy(ANALYTICS_SESSIONS_ENABLED)`, so it has no effect unless `ANALYTICS_ENABLED` is also truthy. Rest of the Analytics section stays available when disabled.                                                           |
| `ANALYTICS_PUBLIC_URL`            | unset   | No                | Preview. The Analytics data-access REST endpoint as an _external_ client would reach it, used to prefill the copyable snippets in a table's Connect panel. Distinct from `DIAL_ANALYTICS_API_URL`, which is how the app itself reaches the service and is commonly an in-cluster address. When unset the snippets show a `<analytics-base-url>` placeholder. |
| `ANALYTICS_FLIGHT_SQL_PUBLIC_URL` | unset   | No                | Preview. The Arrow Flight SQL endpoint as an external client would reach it, e.g. `grpc://analytics.example.com:32010`. Not derived from `ANALYTICS_PUBLIC_URL` — separate gRPC port, different scheme, commonly a different host. When unset the snippets show a `grpc://<analytics-host>:32010` placeholder.                                               |

**Helm `values.yaml` (only if enabling the Analytics session trace view or prefilling Connect snippets):**

```yaml
frontend:
  env:
    ANALYTICS_ENABLED: 'true'
    ANALYTICS_SESSIONS_ENABLED: 'true'
    ANALYTICS_PUBLIC_URL: 'https://analytics.example.com'
    ANALYTICS_FLIGHT_SQL_PUBLIC_URL: 'grpc://analytics.example.com:32010'
```

Both `ANALYTICS_PUBLIC_URL` and `ANALYTICS_FLIGHT_SQL_PUBLIC_URL` affect only the copyable snippets shown to users — leaving them unset degrades the snippets to placeholders and breaks nothing.

**What the migration covers (informational):** the `Catalog` group — Platform Models, Interceptors, Translators, Routes, App Runners, Roles, and Keys, on the `/platform-*` routes — reads and writes DIAL Core config resources directly instead of proxying through the admin backend, which is being phased out. The group is marked `isPreview` in the menu configuration.

## Pre-flight Checklist

- [ ] Add `catalog` to `frontend.env.DISABLE_MENU_ITEMS` (recommended while the migration is Preview)
- [ ] Confirm `DIAL_CORE_API_URL` is set (required since 0.19.0)
- [ ] Keep `DIAL_ADMIN_API_URL` set so the admin-backend-backed menu groups remain available
- [ ] Decide whether to enable the Analytics session trace view (`ANALYTICS_SESSIONS_ENABLED` — requires `ANALYTICS_ENABLED` truthy)
- [ ] If Analytics is enabled, decide whether to set `ANALYTICS_PUBLIC_URL` / `ANALYTICS_FLIGHT_SQL_PUBLIC_URL` so the Connect snippets are prefilled with externally reachable addresses
- [ ] Verify the deployed frontend receives these env vars at runtime
- [ ] Smoke test after upgrade: the `Catalog` group is absent from the sidebar, and `Entities` / `Builders` / `Access Management` / `Audit` still render
